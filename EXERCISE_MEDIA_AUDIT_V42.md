# START/NOW Exercise Media Audit — v42

## Root cause found in v41

The fallback itself was working. The retrieval architecture was the problem.

`exercise-media-provider-v41.js` searched wger live every time an uncached exercise was opened. The search used fuzzy discovery (`name__search`), but a result was only accepted when a provider translation/alias exactly matched one of START/NOW's accepted strings. That combination rejected many legitimate naming variants.

Other v41 coverage problems:

- its alias table covered only a subset of START/NOW's 250 exercises;
- images marked AI-generated by the provider were deliberately rejected, which was correct but reduced the remaining media pool;
- many wger exercises do not have usable non-AI video/image media;
- `unavailable` results were cached for 7 days, so one failed lookup could keep showing the fallback for a week;
- the system still depended on an external API request/CORS/network search at exercise-open time.

The result was exactly what testing showed: the safe fallback appeared correctly, but real media coverage was extremely low.

## v42 architecture

v42 removes live exercise search completely.

The active system is now:

1. START/NOW internal exercise ID
2. deterministic canonical exercise ID
3. curated static manifest lookup
4. approved media asset(s)
5. safe fallback if there is no approved entry

There is no random result selection and no AI image generation.

Every current exercise receives a canonical ID from its stable internal ID. Explicit aliases are used only when two labels are intentionally equivalent. Distinct variations remain distinct. Examples:

- `calf-raise` / `standing-calf-raise` -> `standing_calf_raise`
- `seated-calf-raise` remains `seated_calf_raise`
- `barbell-bench-press` remains `barbell_bench_press`
- `dumbbell-bench-press` remains `dumbbell_bench_press`
- `smith-machine-bench-press` remains `smith_machine_bench_press` and currently falls back unless an exact approved Smith demonstration is added
- `romanian-deadlift` / `barbell-romanian-deadlift` -> `barbell_romanian_deadlift`
- `dumbbell-romanian-deadlift` remains a separate canonical ID and is not allowed to borrow the barbell demo

## Media source

v42 currently uses curated start/end media from the public **Free Exercise DB** project. Its repository describes the dataset as an open public-domain exercise dataset with 800+ exercises and provides two image paths per exercise. The repository is released under the Unlicense.

START/NOW does **not** download the entire source database at runtime. The app contains only a small local manifest of approved source exercise IDs. When an exercise is displayed, only that exercise's two image files are requested.

Current media type is `image-pair`: two real pre-made source images showing the exercise positions. The renderer is already structured to also support verified GIF/video/image entries later.

## Programmatic full-library audit

At startup, v42 enumerates the entire actual `exerciseLibrary` without loading the media files and creates:

```js
window.START_NOW_EXERCISE_MEDIA_AUDIT
window.START_NOW_EXERCISES_NEEDING_MEDIA
window.START_NOW_BROKEN_EXERCISE_MEDIA
```

The full report contains one row for every exercise with:

- exact internal ID
- exact exercise name
- canonical ID
- status (`verified`, `missing`, or `broken`)
- media type
- source
- source exercise ID/name
- failure reason

To print the exact current report and the complete missing/broken lists:

```js
START_NOW_EXERCISE_MEDIA.report()
```

It prints:

```text
Total exercises: X
Verified demonstrations: X
Missing demonstrations: X
Broken demonstrations: X
```

and then `console.table(...)` for every missing or broken exercise. Because this is generated from the live 250-exercise library, it stays accurate if exercises are later added or renamed.

## Runtime debugging

Every displayed exercise logs a structured entry such as:

```text
[Exercise Media]
exerciseDisplayed: Calf Raise
internalId: calf-raise
canonicalId: standing_calf_raise
assetFound: true
assetType: image-pair
source: Free Exercise DB
sourceExercise: Standing Calf Raises
failureReason: null
```

If a real asset fails to load, the system records the exact failed URL and reason for the current browser session, changes that exercise's audit status to `broken`, logs a warning, and shows the existing `Exercise demonstration unavailable` fallback.

## Accuracy rule

A missing demonstration is acceptable. A misleading demonstration is not.

v42 does not automatically map:

- seated calf raise to standing calf raise;
- dumbbell RDL to barbell RDL;
- Smith bench to barbell bench;
- cable lateral raise to dumbbell lateral raise;
- single-arm/neutral-grip pulldowns to a generic wide-grip pulldown;
- other equipment or setup variations just because the names are similar.

Those stay on the fallback until an exact source asset is reviewed and added to the manifest.
